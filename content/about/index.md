## From Using Systems to Understanding Them

My interest in computing grew out of spending years using, configuring, and troubleshooting Linux distributions (primarily Debian, Fedora, and Ubuntu). I was drawn to the predictability, transparency, and modularity of the Unix ecosystem—how small utilities compose through pipes, how processes interact with the kernel, and how hardware resources can be managed with precision.

For a long time, I interacted with systems primarily as an advanced user and developer. Over time, however, my curiosity fundamentally shifted: **I no longer wanted to simply configure systems; I wanted to understand how they work below the application layer.**

Modern software development often abstracts away the machine behind frameworks, runtimes, and garbage collectors. While these abstractions enable rapid prototyping, they obscure the essential mechanics of computation:
- How does the kernel schedule threads and arbitrate CPU time?
- What happens during a `fork()` and `exec()` sequence at the memory page table level?
- How are synchronization primitives like mutexes and condition variables actually enforced in hardware and the operating system?
- Where do memory leaks, cache misses, and lock contention arise when running high-throughput machine learning inference pipelines?

To answer these questions for myself, I made a deliberate decision to step back from superficial framework churn and rebuild my foundation from first principles.

## Technical Foundations & Trajectory

Rather than claiming expertise I do not have, I treat my undergraduate years as an intensive apprenticeship in core computer science:

1. **Low-Level Programming & Systems (C / Unix)**:
   Completing Harvard's **CS50x** solidified my understanding of manual memory allocation, pointer arithmetic, memory layouts, and data structure implementations in C. I am now channeling this into building Unix primitives from scratch—such as a custom shell (**Seashell**) and concurrent data structures.

2. **Operating Systems & Concurrency**:
   I am fascinated by process lifecycles, inter-process communication (IPC), pipes, signals, virtual memory, and multithreaded synchronization. Writing thread-safe data structures has taught me how subtle concurrency bugs and race conditions emerge without disciplined locking and memory barriers.

3. **Algorithms & Computational Thinking**:
   I believe that strong algorithmic intuition is non-negotiable for serious systems and machine learning work. Having worked through fundamental data structures (hash tables, linked lists, tries, binary heaps), I am preparing for Princeton University's *Algorithms, Part I and Part II* to deepen my mastery of graph theory, balanced search trees, and asymptotic analysis.

4. **Artificial Intelligence & Systems for ML**:
   As a student specializing in AI/ML, my perspective is shaped by systems thinking. Rather than treating ML as an opaque library call, I am interested in how machine learning systems scale: resource monitoring (GPU memory and VRAM utilization), inference latency bottlenecks, and applying NLP models to automated developer workflows.
